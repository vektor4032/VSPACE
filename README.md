# VSPACE — Personal Digital Universe

Персональное приложение для планов, привычек, творческих проектов и питания. React 19, TypeScript, Vite, Tailwind CSS 4, Motion, React Three Fiber / Three.js, Lucide, IndexedDB и PWA.

## Запуск

Требуется Node.js 24 LTS и npm. Для локального режима регистрация не нужна. Для синхронизации устройств подключите Supabase по [инструкции](docs/SUPABASE.md).

```sh
npm ci
npm run dev
```

Рабочая директория в облачной среде: `/workspace/VSPACE`. Vite слушает `0.0.0.0`, стандартный порт — 5173. Для локальной разработки адрес выводится в терминале.

## Что работает

- **Главная:** приветствие по времени устройства, текущая дата, задачи и привычки на сегодня, реальный прогресс дня и обзор проектов. Хромированный объект WebGL с мягким движением и реакцией на указатель. На смартфонах, при отключении 3D и сокращённых анимациях — лёгкая CSS-графика.
- **Привычки:** создание, редактирование, удаление с подтверждением, дневные цели, счётчик и сброс, история по датам, heatmap за 7/30 дней, серии. Отдельные записи сна, энергии и настроения.
- **Планер:** создание, редактирование, выполнение и удаление задач, дата, приоритет, ежедневное/еженедельное повторение, день/неделя/месяц, фильтры, прямой переход к дате. Просроченные незавершённые задачи показаны отдельно и переносятся на сегодня одним нажатием. Выполнение повторяющейся задачи создаёт следующую. На компьютере задачи перетаскиваются между днями; на телефоне дата меняется в форме.
- **Проекты:** категории, приоритет, статус, дедлайн, этапы с чекбоксами, прогресс по этапам, текстовые материалы, ссылки на Figma, Behance и другие HTTPS/HTTP-ресурсы. Поиск и фильтр статусов. Файловых вложений пока нет.
- **Рецепты:** 6 практичных рецептов с ингредиентами и инструкциями, поиск по названию и ингредиентам, категории, избранное, пересчёт ингредиентов на 1–12 порций, меню по датам и приёмам пищи. Калорийность приблизительная.
- **Аналитика:** реальные завершения задач и привычек за 7/30 дней, средний сон и энергия по записям самочувствия, отдельные графики сна, энергии и настроения с разрывами на пропущенных днях, регулярность и достижения. Пустые состояния вместо выдуманных результатов; график доступен и в текстовом представлении.
- **Настройки:** профиль, личный фокус (также виден на главной), две тёмные темы, три акцента, управление анимациями и 3D, экспорт/импорт JSON, удаление всех личных данных с подтверждением.

## Данные и приватность

Без входа данные автоматически сохраняются в IndexedDB (`vspace`, store `universe`) этого браузера. После подключения Supabase и входа используется отдельный кеш аккаунта, а записи синхронизируются с его облачной строкой. Аналитических трекеров нет. Шрифты Golos Text и Unbounded поставляются локально через Fontsource (OFL).

Реализованы регистрация, вход, восстановление пароля и синхронизация устройств через Supabase. Для активации нужны внешний проект, SQL-миграция и публичная конфигурация; без них приложение работает локально. Очистка данных сайта/браузера удаляет локальные записи и неотправленные правки. Используйте **Настройки → Экспорт JSON** для резервной копии. Импорт проверяет версию, типы, диапазоны, даты, URL и повторяющиеся идентификаторы. Лимит — 5 МБ; перед заменой требуется подтверждение. Данные не зашифрованы отдельным паролем: доступ к профилю браузера означает доступ к локальной базе.

В заголовке отображается статус записи: «Сохраняем…», «Сохранено локально» или «Не сохранено». Перед перезагрузкой или закрытием дождитесь подтверждения сохранения. Запись проверяет ревизию внутри транзакции IndexedDB: если данные изменились в другой вкладке, устаревший снимок не заменяет актуальный. При конфликте экспортируйте свои изменения и перезагрузите страницу. Автоматического объединения правок пока нет. Если база не читается, приложение показывает экран восстановления и блокирует запись, оставляя исходные записи без изменений.

Начальные личные данные пустые. Только рецепты являются готовым контентом. Кольца, графики и достижения вычисляются из фактических действий.

## Архитектура

```text
src/
  App.tsx               # Оболочка, маршруты, загрузка и очередь сохранения
  context.ts            # Контекст, навигация, форматирование
  data.ts               # Типы/Zod, импорт, бизнес-логика, рецепты
  storage.ts            # Транзакции IndexedDB и метаданные синхронизации
  cloud/                # Supabase Auth, транспорт, трёхстороннее слияние, очередь и UI
  components/
    ui.tsx              # Диалоги, кнопки, кольца, заголовки и пустые состояния
    Tasks.tsx           # Общие форма и строка задачи
  pages/                # Home, Habits, Planner, Projects, Food, Insights, SettingsPage
  Orb.tsx               # Ленивая загрузка WebGL-сцены
  styles.css            # Палитра, композиция, адаптивность и reduced-motion
```

`StorageAdapter` отделяет локальное хранение от бизнес-логики. Модули `src/cloud` добавляют синхронизацию: очередь записи, трёхстороннее слияние, проверку ревизий, офлайн-кеш, изоляцию аккаунтов и авторизованный транспорт. Миграция с RLS и RPC находится в `supabase/migrations`. Пошаговое подключение: [docs/SUPABASE.md](docs/SUPABASE.md). В клиент разрешён только публичный Publishable/anon key.

Навигация использует hash-маршруты: статический хостинг не требует специальных rewrite-правил. Приложение поддерживает видимый focus, клавиатурные формы, нативные модальные диалоги с Escape и возвращением фокуса, `prefers-reduced-motion`. На мобильном устройстве есть нижняя навигация, остальные разделы доступны через «Ещё».

## Проверки

```sh
npm test              # Логика данных, хранение, синхронизация и PostgreSQL/RLS
npm run build         # TypeScript + production + service worker
npm run test:e2e      # Сценарии Chromium, включая мобильные экраны и два устройства
npm run test:pwa      # Production-сборка и офлайн-перезагрузка в Chromium
```

E2E-тесты автоматически запускают dev-сервер на порту 4173. PWA-проверка использует порт 4174. Не занимайте эти порты при запуске соответствующих проверок.

В этой облачной среде используется `/usr/bin/chromium`. На другой машине выполните `npx playwright install chromium`; либо укажите путь в `VSPACE_CHROMIUM`. Для Linux могут понадобиться системные библиотеки Playwright. Тесты создают изолированные браузерные профили и не изменяют личные данные в вашем браузере.

Проверены: полный цикл задач, сохранение после перезагрузки, привычки и реальная аналитика, этапы проектов и внешние ссылки, порции/избранное/меню, профиль/экспорт/ошибочный и корректный импорт, перенос задач, обработка просроченных дел, конфликт правок из двух вкладок, защита нечитаемых данных, динамика самочувствия с пропусками, все 7 экранов при ширине 390 px, закрытие диалога с клавиатуры. Отдельно проверены активный service worker, офлайн-перезагрузка и доступность 6 рецептов без сети.

## Публикация

```sh
npm ci
npm run build
npm run preview       # Только локальная проверка production-сборки
```

Опубликуйте содержимое `dist/` на статическом HTTPS-хостинге (например, Netlify, Vercel или Cloudflare Pages): build command `npm run build`, output directory `dist`, Node 24. Конфигурация рассчитана на корень домена. Для подпапки нужно согласованно настроить `base`, `start_url` и пути иконок в `vite.config.ts`.

PWA работает в production на HTTPS (или локальном loopback для тестирования). После первого онлайн-посещения интерфейс, шрифты, графика и рецепты кэшируются; IndexedDB доступна без сети. Установка — через меню поддерживаемого браузера. Очистка кэша/данных сайта удаляет офлайн-ресурсы и личные записи. Сервер разработки service worker не регистрирует. Реальная установка PWA на iOS/Android отдельно не проверялась.

Сборка готовит артефакты, но не публикует сайт и не отправляет изменения в GitHub. Для облачной среды отдельно проверьте сохранённые инструкции и опубликуйте подготовленную среду через её настройки.

## GitHub Pages

Готовый сайт публикуется из ветки `gh-pages`. В GitHub откройте **Settings → Pages → Build and deployment → Deploy from a branch**, выберите **gh-pages / (root)** и сохраните. Адрес после успешной публикации: `https://vektor4032.github.io/VSPACE/`.

Для сборки под GitHub Pages в PowerShell:

```powershell
$env:VSPACE_BASE_PATH = "/VSPACE/"
npm run build
```

Для обычной локальной разработки переменная не требуется. `dist/` содержит результат сборки, исходный код находится в `main`.

Облачные сценарии проверяются на тестовом HTTP API, а RLS — в PostgreSQL/PGlite. Работа с реальной базой и доставка писем требуют отдельной проверки после подключения вашего проекта Supabase.
